# 001 · 关系型数据库选型

- **日期**: 2026-06-04
- **状态**: ✅ 已采纳

## 背景

项目需要持久化日语单词、收藏记录、文章等结构化数据。需要一个关系型数据库支持 CRUD 和分页查询。

## 方案

**开发环境使用 SQLite，生产环境切换 MySQL。**

### 选型逻辑

| 维度 | SQLite | MySQL |
|------|--------|-------|
| 开发体验 | 🏆 零配置，文件即数据库 | ❌ 需要安装服务、创建数据库 |
| 部署 | 🏆 单文件，随项目分发 | ❌ 需要 Docker / 独立部署 |
| 生产环境 | ❌ 并发写入弱 | 🏆 成熟稳定，支持连接池 |
| ORM 支持 | ✅ SQLAlchemy 一致 | ✅ SQLAlchemy 一致 |

通过 `USE_SQLITE=true` 环境变量控制，底层 ORM 代码完全一致，切换只需改连接串。

### 数据模型

```
words          — 日语单词（表记、假名、中文释义、例句JSON）
favorites      — 用户收藏（word_id + user_id 联合唯一）
articles       — 生成的文章（标题、日语正文、中文翻译、级别）
article_words  — 文章-单词多对多关联表
```

## 备选方案

- **PostgreSQL**: 功能更强大，但对 Windows 用户部署复杂度高
- **DuckDB**: 嵌入式 OLAP，不适合 OLTP 场景

## 后果

- ✅ 开箱即用，不依赖外部服务
- ✅ 开发/生产环境隔离清晰
- ⚠️ SQLite 不支持 `ORDER BY RANDOM()` 在大数据集上的性能，但本项目数据量极小，无影响
