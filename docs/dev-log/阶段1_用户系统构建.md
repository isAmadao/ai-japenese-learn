### 2026-07-07：架构设计与 RS256+JWKS 实现

#### 完成内容

- **架构决策**：将 auth-kit 从 `ai-japenese-learn/auth-kit` 迁入 `myProject/auth-kit`，再合并到 `auth-service/auth_kit/` 作为内部包
- **RS256 签名**：auth-service 用 RSA 私钥签名 JWT，auth-client 用公钥验签，不再共享密钥
- **JWKS 端点**：`GET /.well-known/jwks.json` 暴露公钥，支持客户端自动发现
- **Token 版本号**：User 模型添加 `token_version`，改密/封禁时 +1，旧 token 立即失效
- **JTI 黑名单**：退出登录时 token 的 `jti` 加入 Redis 黑名单，支持实时撤销
- **Token Introspection**：`POST /api/auth/introspect` 端点，供需要实时验证的服务调用

#### 问题 & 解决方案

**问题1：auth-kit 位置不合理**

现象：`auth-service` 通过 `pip install -e` 引用 `ai-japenese-learn/auth-kit`，跨项目引用不清晰
根因：`fastapi_auth_kit` 的核心代码在另一个项目里
解决：先迁到 `myProject/auth-kit`，最终合并到 `auth-service/auth_kit/` 作为内部包
效果：`auth-service` 自包含，不需要 pip 外部包

**问题2：SQLite check_same_thread 错误**

现象：`sqlite3.ProgrammingError: SQLite objects created in a thread can only be used in that same thread`
根因：`check_same_thread=True` 导致 uvicorn 多线程环境崩溃
解决：`connect_args={"check_same_thread": False}`
效果：auth-service 在 uvicorn 多线程模式下正常运行

**问题3：logout 端点 import 缺失**

现象：`NameError: name 'decode_access_token' is not defined`
根因：`api/auth.py` 的 logout 函数引用 `decode_access_token` 但未 import
解决：在 `api/auth.py` 的 import 列表中加入 `decode_access_token`
效果：logout 端点正常工作

**问题4：admin 账号未自动创建**

现象：首次启动 auth-service，admin/admin 无法登录
根因：`auth_kit.initialize()` 不自动 seed admin，需要显式调用 `seed_admin()`
解决：`main.py` 初始化后调用 `auth_kit.seed_admin(db)`
效果：首次启动自动创建 admin/admin 账号

**问题5：Vite 代理 `localhost` 与 `127.0.0.1` 差异**

现象：通过 Vite 代理 `/api/favorites` 返回 401，直连 backend 正常
根因：Windows 上 `localhost` 可能解析到 IPv6 `::1`，而 uvicorn 绑定在 `127.0.0.1`(IPv4)
解决：Vite proxy target 改为 `http://127.0.0.1:8000`
效果：前端页面正常访问业务 API
